# dsh-purge-master-vm

在隔离 Windows 10 虚拟机里准备 **dsh 红队评测环境** 的操作笔记与命令清单。

> **适用范围**：仅自有或书面授权的本机 / 回环 / 私网靶场，以护栏有效性评测为目的。
> 不对公网目标、第三方平台、生产系统或真实用户数据使用；不改动工具自带的私网靶场与反外挂限制。
> 本仓库**不含插件源码**，也**不提供**关闭护栏、绕过拒绝钩子的操作步骤。

## 目录

| 文件 | 内容 |
|---|---|
| `docs/vm-setup.md` | 主文档：授权与范围、隔离检查、环境要求、版本选型、安装命令、排错表 |
| `NOTICE.md` | 上游项目与第三方许可署名 |
| `.gitignore` | 排除源码包、依赖、凭据、日志与临时文件 |

命令中的 `admin`、`<USER>`、`<DATE>`、`<VM 内实际路径>` 均为占位符，按实际环境替换。

## 快速开始

1. 填好 `docs/vm-setup.md` 第零章的授权表 —— 这是前置条件，未完成不开始任何测试动作。
2. 准备一台隔离 VM（NAT 或 host-only），打命名快照 `pre-redteam-<DATE>`。
3. 按 `docs/vm-setup.md` 第三节「最终方案 B 执行清单」执行，**到只读验证为止**。
4. 评测设计见第零章：干净对照组 vs 评测组，产出护栏有效性与误报 / 漏报分布。

## 版本组合

| 方案 | dsh 本体 | 插件 | 适用 |
|---|---|---|---|
| A 开箱即用 | `0.2.1-rc.5` | `dsh-purge-community` 1.6.74 | 不降级、功能较全 |
| B 研究 / 二开（本文默认） | `0.2.1-rc.2` | `dsh-purge` 1.1.90 | 源码在手、零第三方依赖、干扰变量最少 |

两者的适配声明都存在自相矛盾之处，一律以 `dsh --profile web --dump-config` 实测为准。

## 准备源码物料

本仓库**不分发第三方源码**。二选一：

- **推荐：直链安装**（零文件传输），在 VM 内执行：

```powershell
dsh plugin --profile web add https://codeload.github.com/HunYiSage/dsh-purge/tar.gz/refs/heads/master
```

- **本地源码**：从上游取得源码目录后，在宿主机排除 `.git` / `node_modules` 打包成
  `dsh-purge-master.zip`（解包后顶层须为 `dsh-purge-master/`），再经 VMware Tools 拖放进 VM。
  zip 属构建产物，不入库，见 `.gitignore`。

## 边界

- 授权表未完成，不开始任何测试动作。
- 「应用 / 生效」环节由操作者本人在隔离 VM 内确认；本仓库不展开其操作步骤。
- 评测结论用于改进防护与提示设计，不用于提炼规避手法。
- 对照实验请用另一台 VM 或回滚快照后重装：改动落在全局宿主层，同一 VM 多 profile 不隔离。
- 不把宿主 harness 主目录挂成 VM 的可写工作区；不复制宿主机凭据文件，使用 VM 独立 API key。
